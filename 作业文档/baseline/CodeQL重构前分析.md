# CodeQL重构前分析

## 1. 基本情况

- 分析工具：`CodeQL`
- 分析方式：通过 GitHub Actions 手动触发 `CodeQL` 工作流
- 分析阶段：重构前基线阶段
- 运行结果：工作流执行成功，`Code scanning` 页面显示 `0 alerts`

本次分析的主要目的不是单纯寻找语法错误，而是验证项目是否已经成功接入自动化静态分析流程，并记录当前仓库在 CodeQL 查询规则下的基线结果。

## 2. 运行结果说明

在本次重构前基线建立过程中，项目已经成功完成以下步骤：

- 成功触发 GitHub Actions 中的 `CodeQL` 工作流
- `Analyze (python)` 任务执行成功
- GitHub `Security and quality -> Code scanning` 页面正常显示扫描结果
- 当前扫描结果为 `0 alerts`

这说明：

- `CodeQL` 工具链已经正常接入项目
- 工作流配置和扫描流程已经能够稳定运行
- GitHub 可以正常接收并展示扫描结果

因此，从实验基线的角度来看，`CodeQL` 部分已经建立成功。

## 3. 为什么会出现 0 alerts

`0 alerts` 并不表示“CodeQL 没有运行”，而是表示：

> CodeQL 已经成功完成扫描，但在当前默认查询规则下，没有发现需要在 `Code scanning` 页面报告的安全告警。

对于本项目而言，出现 `0 alerts` 是合理的，主要原因如下。

### 3.1 项目类型决定了安全风险暴露面较小

当前实验对象是一个本地命令行版图书馆管理系统，其主要特征包括：

- 本地运行
- 使用 JSON 文件进行数据持久化
- 没有开放 Web 接口
- 没有数据库连接
- 没有复杂的网络输入输出链路

相较于 Web 系统、开放 API、数据库驱动型系统或分布式服务，这种命令行应用暴露的典型安全风险面更小，因此不容易触发 CodeQL 常见的高风险规则。

### 3.2 当前项目的主要问题不是“安全漏洞”，而是“结构质量问题”

结合人工审查、Pylint 和 Radon 的分析结果可以看出，本项目当前更突出的质量问题主要集中在以下方面：

- 函数过长
- 分支过多
- 菜单逻辑和业务逻辑耦合
- 服务层职责过重
- 命名不够清晰
- 文档字符串和注释缺失
- 可测试性支持不足

这些问题会显著影响可读性、可修改性和可测试性，但它们通常不会直接被 CodeQL 作为 `alert` 报出。  
也就是说，CodeQL 关注的是“是否存在符合安全规则或特定缺陷模式的问题”，而不是“代码结构是否优雅”。

### 3.3 CodeQL 与 Pylint / Radon 的关注点不同

本次实验中使用的三个主要静态分析相关工具，其关注重点并不相同：

- `Pylint`：关注命名、风格、函数规模、结构规范和常见代码异味
- `Radon`：关注复杂度、可维护性和代码规模
- `CodeQL`：关注安全告警、危险代码模式以及部分静态缺陷

因此，出现以下情况是正常的：

- `Pylint` 检测到较多规范和结构问题
- `Radon` 检测到复杂度热点和可维护性问题
- `CodeQL` 显示 `0 alerts`

这并不矛盾，而是说明项目当前的主要短板在“维护质量”，不在“安全告警”。

## 4. 本结果在实验中的意义

虽然 `CodeQL` 的结果为 `0 alerts`，但这一结果仍然具有明确的实验价值。

### 4.1 证明自动化静态分析流程已成功接入

本次扫描成功说明项目已经具备以下条件：

- GitHub Actions 工作流配置正常
- CodeQL 可以自动运行
- 扫描结果能够被 GitHub `Code scanning` 页面接收和展示

这意味着项目已经具备“自动化质量门禁”的基本条件，后续可以将其作为 CI/CD 质量检查的一部分。

### 4.2 为后续重构提供对照基线

即使当前结果是 `0 alerts`，它仍然是一个有效的“重构前状态”。  
后续在实验中，如果代码结构发生变化、功能增加或规则扩展，再次运行 CodeQL 时就可以与当前结果进行对比。

### 4.3 说明本项目的重构重点应放在结构质量而非安全修复

CodeQL 没有发现安全类告警，反而帮助我们更清楚地确认了实验重点：

- 本项目当前最突出的问题不在安全性
- 当前真正需要优先改进的是可读性、可修改性和可测试性
- 因此实验一与实验二的方向选择是合理的

## 5. 结合本项目的分析结论

结合当前 CodeQL 结果，可以得出以下结论：

1. `CodeQL` 已经成功接入本项目  
   工作流运行成功，说明静态分析自动化链路可用。

2. 当前仓库没有发现 Code scanning 告警  
   `0 alerts` 说明在 CodeQL 默认查询规则下，没有发现明显的安全类问题。

3. 本项目的主要质量问题集中在结构和维护层面  
   当前项目的问题更适合通过人工审查、Pylint 和 Radon 来揭示，而不是依赖安全扫描告警。

4. CodeQL 结果与实验主题并不冲突  
   本次实验关注的是可读性、可修改性和可测试性，而不是安全漏洞修复，因此 `0 alerts` 属于合理且可接受的结果。
