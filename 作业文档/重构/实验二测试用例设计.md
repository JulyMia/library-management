# 实验二测试用例设计

## 1. 设计目标

本测试用例文档围绕图书馆管理系统的核心业务路径编写，重点覆盖以下三类内容：

- 核心正常路径：验证新增图书、新增用户、借书、还书等主流程是否正确执行。
- 关键边界路径：验证重复借阅、库存不足、用户状态异常、重复归还等高风险场景。
- 纯逻辑路径：验证逾期判断与逾期天数计算等不依赖 CLI 的业务规则。

本次测试主要面向 `LibraryService` 和 `BorrowRecord` 两个核心测试对象，尽量避开命令行输入输出，以保证测试稳定、可重复、便于自动回归。

## 2. 测试范围

- 服务层：
  - `add_book()`
  - `add_user()`
  - `borrow_book()`
  - `return_book()`
  - `get_overdue_records()`
  - `update_book()`
- 模型层：
  - `BorrowRecord.calculate_overdue_days()`
  - `BorrowRecord.is_overdue()`

## 3. 测试环境与策略

- 测试框架：`pytest`
- 测试目录：`tests/`
- 数据隔离方式：使用 `JsonStorage(base_dir=tmp_path)` 将测试数据写入临时目录，避免污染真实 `books.json`、`users.json`、`records.json`
- 测试组织方式：
  - `tests/conftest.py`：公共夹具
  - `tests/test_services.py`：服务层业务测试
  - `tests/test_models.py`：模型层纯逻辑测试

## 5. 重点说明

### 5.1 为什么重点测试服务层

- `LibraryService` 集中了图书、用户、借阅、归还、逾期与统计等核心业务规则。
- CLI 层主要负责输入采集和结果展示，交互因素较多，不适合作为本次实验二的测试重点。
- 因此本次测试优先覆盖服务层，有利于验证“结构重构后业务逻辑是否仍然正确”。

### 5.2 为什么引入临时目录隔离

- 如果直接让测试操作项目根目录下的 JSON 文件，会污染真实实验数据。
- 使用 `tmp_path` 可以为每次测试创建独立临时目录，使测试具备可重复性与隔离性。
- 这也是本次实验中“可测试性改造”的重要体现之一。

### 5.3 为什么保留模型层测试

- `BorrowRecord.calculate_overdue_days()` 与 `BorrowRecord.is_overdue()` 属于典型纯逻辑方法。
- 这类方法不依赖 CLI，不直接触发真实文件保存，最适合做稳定的单元测试。
- 模型层测试可以补足“服务流程正确，但底层规则计算错误”的风险。
