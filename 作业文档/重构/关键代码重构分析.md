# 关键代码重构分析

## 关键代码一：借书流程从集中式校验改为分阶段校验

### 重构前节选
```python
user = None
for item in self.users:
    if item.user_id == user_id:
        user = item
        break
if user is None:
    return False, "用户不存在。"
if user.status != "正常":
    return False, "用户状态异常，不能借书。"

book = None
for item in self.books:
    if item.book_id == book_id:
        book = item
        break
if book is None:
    return False, "图书不存在。"
```

### 重构后节选
```python
user = self._find_user_obj(user_id)
if user is None:
    return False, "用户不存在。"
book = self._find_book_obj(book_id)
if book is None:
    return False, "图书不存在。"
is_valid, message = self._validate_borrow_request(user, book)
if not is_valid:
    return False, message
record, due_date = self._create_borrow_record(user, book, note)
book.available_count -= 1
self.records.append(record)
self._save_books_and_records()
```

### 分析
- 重构前把查找对象、校验状态、判断库存、统计借阅上限、检查重复借阅、创建记录全部塞在一个方法里，函数职责过重。
- 重构后通过 `_validate_borrow_request()` 和 `_create_borrow_record()` 把借书过程拆成对象获取 -> 规则校验 -> 执行借阅三个阶段，主流程更接近业务语义，且保存操作也统一收敛到 `_save_books_and_records()`。
- 这种改法最直接的收益是：后续如果要新增教师用户可多借 5 本之类规则，只需要修改校验辅助函数，而不是在主流程里继续堆条件。

## 关键代码二：图书修改逻辑从内联更新改为辅助方法承载复杂字段处理

### 重构前节选
```python
if "isbn" in info and str(info["isbn"]).strip():
    new_isbn = str(info["isbn"]).strip()
    flag = False
    for item in self.books:
        if item.book_id != book_id and item.isbn == new_isbn:
            flag = True
            break
    if flag:
        return False, "ISBN 与其他图书重复。"
    data.isbn = new_isbn
if "total_count" in info and str(info["total_count"]).strip():
    total = int(info["total_count"])
    diff = total - data.total_count
    data.total_count = total
    data.available_count = max(0, data.available_count + diff)
```

### 重构后节选
```python
book_to_update, error_message = self._get_book_or_error(book_id)
if error_message:
    return False, error_message
is_updated, message = self._apply_book_updates(book_to_update, info)
if not is_updated:
    return False, message
self._save_books()
return True, "图书信息修改成功。"
```

### 分析
- 重构前的 `update_book()` 同时负责查找图书、字段解析、唯一性校验、库存修正和保存，导致复杂度非常高。
- 重构后公开方法只保留获取对象 + 调用更新 + 保存的骨架，复杂字段处理移动到 `_apply_book_updates()`。
- 这样虽然辅助函数本身仍有一定复杂度，但复杂度被封装到了更合适的局部位置，公开接口更短、更利于阅读和后续测试；这也是最终 `Radon` 中 `update_book()` 下降到 `A (4)` 的直接原因之一。

## 关键代码三：菜单控制从 if/elif 链改为统一菜单分发

### 重构前节选
```python
while True:
    show_menu("图书管理", [...])
    choice = input("请选择功能编号: ").strip()
    if choice == "1":
        self._handle_add_book()
    elif choice == "2":
        self._handle_delete_book()
    elif choice == "3":
        self._handle_update_book()
    elif choice == "4":
        self.search_books_menu()
    elif choice == "5":
        self._handle_show_books()
    elif choice == "6":
        break
```

### 重构后节选
```python
self._run_menu_loop(
    "图书管理",
    [
        "添加图书",
        "删除图书",
        "修改图书信息",
        "查询图书",
        "显示全部图书",
        "返回主菜单",
    ],
    {
        "1": self._handle_add_book,
        "2": self._handle_delete_book,
        "3": self._handle_update_book,
        "4": self.search_books_menu,
        "5": self._handle_show_books,
    },
    "6",
)
```

### 分析
- 重构前的菜单函数高度重复，`book_menu()`、`user_menu()`、`borrow_menu()`、`overdue_menu()` 都在重复展示菜单 -> 判断输入 -> 调用处理器的模板。
- 重构后通过 `_run_menu_loop()` 抽出共性流程，子菜单只保留配置项和处理器映射，代码结构明显更清晰。
- 这种重构属于典型的提取模板方法，它不会改变业务结果，但能显著降低分支复杂度和重复率，是本次实验最容易量化体现收益的改动之一；最终 `book_menu()` 和 `user_menu()` 的复杂度都下降到 `A (1)`。

## 综合结论
- 三个关键改动分别作用在业务主流程、复杂字段更新和 CLI 菜单分发三个层面。
- 它们共同体现出的重构思想是：把主流程保留为简短骨架，把变化点和细节处理下沉到小函数中，并在最终阶段补足必要的说明性文档字符串。
- 这种方式虽然让代码文件变长了一些，但明显提升了阅读顺序、修改定位效率和后续测试可切入性，也让最终的 `Pylint` 与 `Radon` 结果更稳定、更容易解释。
